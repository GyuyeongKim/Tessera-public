A join-aggregate counts, for every pair of values, the rows they share. Here the rows are the words of New York Times articles, and the query asks which words appear together. DuckDB and Tessera run the same SQL on the same rows, each on one thread of your browser, and return the same answer.

Where the time goes

    
DuckDB's join emits a row for every two words that share an article, millions of
    rows here, and its aggregation updates a hash table for each of them. Tessera never builds these rows. It adds the
    pairs of each article into an array of counters and writes only the pairs that occur.

    
With a top 10 or a threshold, the engine can filter only after it has counted every pair. Tessera first bounds how
    often each word can appear in a pair and drops the words that cannot qualify, so a stricter query runs faster.

    
In this page both engines use one thread and no matrix accelerator. On a server, Tessera also uses every core and
    runs the most frequent words on the CPU's matrix accelerator, such as Intel AMX.
